# HOUZZkit F1 第一期 SSD 管理方案

第一期为 Ubuntu 和 Armbian 的 htoold 工作台增加「SSD 管理」页面。用户在此查看 NVMe SSD、初始化数据盘，并把已经使用的 Docker 数据从 eMMC 迁到 SSD。系统根文件系统和启动链继续位于 eMMC。通用备份还原、恢复出厂和固件在线更新在后续阶段实施。迁移前按现有流程备份涉及的业务数据。

## 页面和状态

工作台侧栏加入「SSD 管理」，路由为 `/storage/ssd`，沿用现有管理员会话和首启跳转规则。页面显示磁盘型号、容量、分区、挂载点、可用空间和当前 Docker 数据位置。磁盘识别以系统报告的 NVMe 设备、分区及稳定标识为准，页面上的设备名仅用于显示。

| 状态 | 页面可用操作 |
| --- | --- |
| 未检测到 SSD | 刷新检测，查看当前 eMMC 存储状态 |
| 已识别，未初始化 | 检查盘上数据，选择是否初始化空盘 |
| 已有可用 ext4 分区 | 选择复用分区，查看空间与预计迁移范围 |
| 迁移中 | 查看复制、核验与切换进度，恢复未完成任务 |
| Docker 已使用 SSD | 查看当前存储位置，核验容器，清理旧副本或迁回 |
| 已配置的 SSD 缺失或不可用 | 查看缺盘或挂载失败原因，重试挂载。系统管理入口保持可用 |

## 初始化与复用

- 支持复用兼容的 ext4 分区，以独立目录承载 Docker 数据，保留分区内其他文件。首次初始化以空的、未被使用的 NVMe SSD 为目标，显示将创建的分区与文件系统。
- 初始化前再次验证管理员身份，展示型号、容量、稳定标识和影响范围。服务端在执行前重新核对磁盘身份，拒绝 eMMC、已挂载分区和系统当前使用的设备。检测到已有数据且不符合复用条件时，提示先备份并通过维护流程准备磁盘。插入 SSD 或打开页面时只进行检测。
- 用文件系统 UUID 挂载到 `/mnt/ssd`。启用后，校验实际挂载点、UUID、文件系统及读写状态。SSD 缺失时仍能从 eMMC 启动系统。

## Docker 数据迁移

1. **预检与备份**。显示 Docker Root Dir、containerd 存储模式、命名卷、已登记的宿主机绑定目录、目标容量和预计停机。用户确认已备份相关数据库、卷和配置。不可确认的绑定目录应在预览中列出，并由用户选择保留原位或纳入迁移。空间不足、目标身份不符或源数据无法完整读取时暂停迁移。
2. **停写与复制**。持久化任务记录，停止受影响的 Compose 栈、Docker 服务和 socket，以及使用迁移目录的 containerd。离线复制并校验数据、UID/GID、权限、ACL、扩展属性和硬链接。迁移覆盖 Docker 镜像、容器元数据和命名卷。按实际存储模式迁移 containerd 数据。迁移绑定目录时同步明确要修改的 Compose 路径。
3. **提交与恢复服务**。校验通过后，在 eMMC 上持久化活动盘 UUID 和有效路径，再启动 Docker。确认 Docker Root Dir、原有镜像、容器和卷可访问。修改了宿主机绑定路径的容器需重新部署，用户原有的 Compose 和 1Panel 配置应随应用保留。用户安装的 1Panel 继续连接同一个宿主 Docker socket，可启动迁移后的容器，也可用已迁移的镜像创建容器。
4. **处理失败或缺盘**。提交前失败，恢复原路径。提交后开机只使用记录中的 SSD，缺盘时暂停依赖它的容器服务并显示原因。重启先恢复未完成任务，再启动依赖数据盘的服务。SSD 已接受新写入后，迁回须停写并将最新数据同步回目标，再提交新位置。
5. **清理原盘副本**。迁移核验通过后，用户可点击「删除原盘副本」。确认前显示旧目录和预计释放空间。后台再次确认当前 Docker、containerd、Compose 和其他已登记应用均未引用这些目录，清理范围限于本次迁移记录中的旧路径。已删除副本时，迁回使用 SSD 当前数据或外部备份。

## 实施与验收

| 任务 | 交付 | 验收 |
| --- | --- | --- |
| 1 · 检测与页面 | SSD 管理菜单、设备状态和管理员鉴权 | 两种固件分别检查无盘、空盘、已有分区和缺盘状态 |
| 2 · 初始化与复用 | 空盘初始化、复用现有 ext4、按 UUID 挂载 | 确认不会改动 eMMC 或未选中的盘，已有数据盘复用后原文件仍可读 |
| 3 · 迁移与恢复 | 导入现有 Docker 数据、记录切换、恢复任务和缺盘处理 | 覆盖空间不足、复制中断、提交前后断电、容器和数据库恢复、SSD 拔除和重新接回 |
| 4 · 迁后管理 | 1Panel 管理、旧副本清理和迁回 | 启动迁移后的容器，核对卷与数据。删除 eMMC 副本后验证 SSD 数据继续可用 |

管理操作由后端校验并串行执行，网页只提交检测到的设备标识和固定动作。可破坏数据的操作有独立确认，任务进度写入 eMMC，刷新页面后可继续查看。每项先做代码和配置的静态检查，最终在 Ubuntu、Armbian 的 F1 实板完成迁移验收。 [Armbian 手动迁移基线](armbian-adaptation.md#4-阶段三可选-ssd-数据盘与迁移)
